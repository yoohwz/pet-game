# Persistence Contract

Local `user://profile.json` is schema v7 and atomically includes pet activity/survival/growth state, relationship/memory and durable memorial snapshots. `growth` persists exact v1 metadata (`growth_version`, `growth_balance_version`, `stage_started_at`); profile simulation persists `simulation_version = 6` and growth balance governance. v6 active pets and nested memorial snapshots receive growth metadata during migration. ALIVE legacy pets may catch up through the next reconciliation, including zero elapsed time; DEAD and memorial history never receives retrospective growth. Eggs retain their lifecycle data. Because Godot JSON parses number literals as floats, the repository migration boundary canonicalizes only mathematically exact whole floats (`value == floor(value)`) for strict integer fields, including growth integers. Fractional values—including near-integers and negative fractions—remain invalid and cannot be saved. `memorial_count` may be greater than `memorials.size()` to preserve pre-snapshot historical memorials, and a new memorial increments that count rather than recalculating it. New Egg eligibility requires a snapshot-backed memorial (`memorial_count > 0` and non-empty `memorials`), and Presentation uses the same predicate so historical count-only state exposes no impossible action. Explicit care candidates atomically include biological, relationship, memory and event changes. Existing validated-temp and known-good backup guarantees remain.

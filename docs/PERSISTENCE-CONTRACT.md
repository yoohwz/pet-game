# Persistence Contract

Local `user://profile.json` is schema v5 and atomically includes pet activity/survival state and durable memorial snapshots. `memorial_count` may be greater than `memorials.size()` to preserve pre-snapshot historical memorials, and a new memorial increments that count rather than recalculating it. v4 pets migrate to `STABLE` survival; v4 eggs/HATCHING reservations are preserved. Explicit care, rescue, memorial and new-egg actions use candidate-save semantics: a persistence failure cannot commit an effect, event, memorial, or active-subject transition. Startup reconciles offline survival and persists any resulting CRITICAL/DEAD state, but never memorializes or issues an egg automatically. Existing validated-temp and known-good backup guarantees remain.
